Introduction

Overview

Qunix is a monolithic kernel written in Rust targeting x86-64, combining language-level memory safety with a full-featured POSIX-compatible userspace environment. It aims to be complete, not minimal.

⚙️

Full Process Model

Complete fork/exec/wait/exit semantics with POSIX signals, job control, sigaction, sigprocmask, and sigreturn.

💾

Virtual File System

Layered VFS abstraction over ext4, FAT32, tmpfs, devfs, and procfs with inode/dentry caching and full mount support.

🧠

Memory Management

Demand-paged virtual memory, Copy-on-Write fork, mmap/munmap/mremap/brk, transparent huge pages, and slab allocator.

⚡

Preemptive Scheduler

Priority-based preemptive scheduler with multi-CPU support, per-CPU run queues, load balancing, and real-time scheduling classes.

🔗

IPC Mechanisms

Pipes with proper EOF/EPIPE semantics, shared memory (shmget/shmat), message queues, semaphores, and futexes with WAIT/WAKE/REQUEUE.

🌐

Networking Stack

Full TCP/UDP implementation with IPv4/v6 routing, BSD socket API, and an io_uring-backed async I/O path.

🛡️

Security

Process namespaces, memory tagging extensions, seccomp system call filtering, and mandatory access control policies.

🔌

Plugin System

Loadable kernel modules with runtime insertion/removal, hook points throughout subsystems, and config-driven management via pluginctl.

Build Guide

Building Qunix

Requires a Linux host (Ubuntu 20.04+ recommended), Rust nightly, and a small set of system tools. The build system is a single shell script.

System Requirements

Linux x86-64 host · 4 GB RAM · 10 GB free disk · Ubuntu 20.04 or newer recommended

Rust Toolchain

Rust nightly ≥ 2024-01, rust-src component, ld.lld ≥ 14, mtools, xorriso, qemu-system-x86_64 ≥ 7.0

bash — 1. Install Dependencies
# Ubuntu/Debian
sudo apt-get install -y lld mtools xorriso qemu-system-x86_64 curl build-essential

# Install Rust nightly
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source $HOME/.cargo/env
rustup toolchain install nightly
rustup component add rust-src --toolchain nightly

# Or use the setup script
./SETUP.sh
bash — 2. Build & Run
# Build kernel only
./build.sh kernel

# Build everything and create bootable ISO
./build.sh iso

# Build and run in QEMU (512 MB RAM, 1 CPU)
./build.sh run

# More RAM, more CPUs
QEMU_MEMORY=2G QEMU_CPUS=4 ./build.sh run

userland/target/x86_64-qunix-user/release/         # userland binaries
qunix.iso                                          # bootable ISO image
Kernel Design

Architecture

Qunix implements a monolithic kernel design — all core services run in kernel space, providing high performance and tight integration while leveraging Rust's ownership system for safety.

🏗️

Monolithic Kernel

All subsystems in kernel space with zero-cost Rust abstractions and no unsafe code outside isolated arch/driver layers.

🔒

Memory Safety

Rust ownership rules eliminate buffer overflows, use-after-free, and data races at compile time throughout the kernel.

🔄

Linux ABI Compat

abi_compat layer provides Linux syscall compatibility, enabling standard toolchains to target Qunix.

Boot Sequence

Boot Process

① UEFI Bootloader

Loads kernel ELF binary and initramfs from the EFI partition. Performs memory map discovery and hands off to kernel_main().

② Hardware Init

Sets up GDT, IDT, TSS. Initializes physical memory allocator using UEFI memory map. Configures paging, PIT, and APIC.

③ Subsystem Init

Initializes VMM, slab allocator, scheduler, device drivers, VFS with essential mounts (tmpfs, devfs, procfs), and networking.

④ Userland Launch

Loads init binary (PID 1) via ELF loader. Init mounts ext4 root, starts qshell, and presents the interactive prompt.

x86-64 Virtual Address Space

Memory Layout

Qunix uses the full 48-bit canonical x86-64 address space split between user and kernel halves.

0x0000_0000_0000_0000 User space start user
0x0000_0001_0000_0000 Heap start (brk) user
0x0000_4000_0000_0000 mmap base user
0x0000_5000_0000_0000 PIE executable base user
0x0000_7FFF_0000_0000 Dynamic linker (ld.so) user
0x0000_7FFF_FFFF_0000 User stack top user
— Canonical Hole —
0xFFFF_8000_0000_0000 Kernel virtual base / direct map kernel
0xFFFF_C000_0000_0000 Kernel heap (vmalloc) kernel
0xFFFF_FFFF_FFFF_FFFF Top of address space kernel

User–Kernel Interface

Syscall ABI

Qunix implements the standard Linux x86-64 syscall ABI — fully compatible with Linux binaries targeting x86_64-qunix-user.

Calling Convention

Uses the syscall instruction for entry and sysretq for return. Syscall number in rax; arguments in rdi rsi rdx r10 r8 r9. Return value in rax.

Coverage

Approximately 250 syscalls including all major POSIX calls and Linux-specific extensions. Unimplemented calls return ENOSYS cleanly.

rust — Adding a Syscall
// 1. Add handler in kernel/src/syscall/handlers.rs
pub fn sys_mysyscall(&mut self, arg1: usize, arg2: usize)
    -> Result<usize, Errno> {
    // implementation
    Ok(0)
}

// 2. Wire into dispatch table in kernel/src/syscall/mod.rs
const MY_SYSCALL: usize = 400;
syscall!(MY_SYSCALL, mysyscall);

// 3. Add libsys wrapper in userland/libsys/src/lib.rs
pub fn mysyscall(arg1: usize, arg2: usize) -> isize {
    unsafe { syscall2(MY_SYSCALL, arg1, arg2) }
}
POSIX Signals

Signal Delivery Flow

Signals are queued in the process control block and delivered at syscall exit, preserving full register state through a user-space signal frame.

send_signal(pid, sig) → p.sig_pending.add(sig) → wake_process(pid) // if sleeping   [at syscall exit in dispatch()] → deliver_pending_at_syscall_exit(frame) → for each pending signal: User handler: build_signal_frame() → patch frame.rip set_user_rsp(new_rsp) Default: apply_default() [terminate / stop / ignore]   [handler runs, calls sigreturn (syscall 15)] → sigreturn(frame) → read SigFrame from get_user_rsp() → restore all regs into SyscallFrame → set_user_rsp(mc.rsp) → return mc.rax

Interactive Shell

qshell

Qunix ships its own POSIX-compatible shell (qshell / qsh) with job control, syntax highlighting, history, and completion.

Shell Features

Pipelines, redirection (> < >>), background jobs (&), job control (Ctrl+Z / fg / bg), command history (up/down), tab completion, and environment variables.

Configuration

Edit ~/.qshrc for aliases, PATH extensions, and environment. Global shell config lives in /etc/profile.

bash — qsh Session Examples
qunix:/root$ ls -la /bin
qunix:/root$ cat /etc/hostname
qunix:/root$ grep -r "pattern" /usr/share | sort | uniq -c
qunix:/root$ ./my_program &
[1] 42
qunix:/root$ jobs
[1]+ Running  ./my_program
qunix:/root$ fg %1

# ~/.qshrc
alias ll='ls -l'
alias la='ls -a'
export EDITOR=nano
export PATH=$PATH:/usr/local/bin
Extensibility

Plugin System

Qunix supports loadable kernel modules called plugins. They can be inserted and removed at runtime and hook into scheduler, syscall, and I/O paths.

📊

perf_monitor

Built-in performance monitoring plugin. Tracks CPU usage, syscall frequency, and scheduler events. Enabled via pluginctl enable perf_monitor.

📝

syscall_logger

Logs all system calls with arguments and return values to the kernel log. Invaluable for debugging userland programs or auditing behavior.

rust — Writing a Plugin
use crate::plugins::{Plugin, PluginMeta, PluginEntry};

pub struct MyPlugin;

impl Plugin for MyPlugin {
    fn init(&self) {
        klog!("My plugin initialized");
    }

    fn deinit(&self) {
        klog!("My plugin deinitialized");
    }

    fn pre_syscall(&self, ctx: &SyscallCtx) {
        // intercept syscalls here
    }

    fn scheduler_tick(&self) {
        // fires on each scheduler timer interrupt
    }
}

plugin_entry!(MyPlugin);
bash — Plugin Management
pluginctl list                         # show all plugins
pluginctl enable  perf_monitor         # load plugin at runtime
pluginctl disable syscall_logger       # unload plugin
